Which table shape for daily rates?

One row per (date, currency) vs one row per date with a JSON column. Recommended: A — it keeps Prisma queries and the outlier job trivial.

A

Row per (date, currency)

Composite unique key, indexable, plain SQL for outliers.

B

Row per date, rates as JSON

One fetch = one insert; every read unpacks JSON.

Shapes side by side
A — schema.prisma
model DailyRate {
  date      DateTime @db.Date
  currency  String   @db.VarChar(3)
  rate      Decimal  @db.Decimal(18, 6)
  @@id([date, currency])
}
B — schema.prisma
model DailyRates {
  date   DateTime @id @db.Date
  rates  Json
}
Response DTO (both)
export interface IGetDailyRatesResponseBody {
  date: string;
  rates: { currency: string; rate: string }[];
}
